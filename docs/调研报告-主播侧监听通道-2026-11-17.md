# 调研报告 A：主播侧监听通道（直播伴侣本机勘察 + 官方接口路线）

> 日期：2026-11-17 ｜ 调研对象：本机正在运行的 抖音直播伴侣 v8.8.0（`D:\douyin\`）+ 官方/生态网络调研
> 目标：评估是否存在**安全、可靠、非侵入**的主播侧互动数据（点赞/弹幕/进场）获取通道，**必须避免任何可能导致封号的做法**。
> 方法声明：本机勘察全程只读（进程/端口/文件/配置/日志/反解 asar 包），未注入、未挂钩、未修改伴侣任何文件与运行状态；未向伴侣或字节服务器发送任何伪造请求。

---

## 一、本机直播伴侣 v8.8.0 只读勘察（全部为直接实证）

### 1.1 进程与安装结构

| 项 | 实测结果 |
|---|---|
| 安装目录 | `D:\douyin\`（版本目录 `8.8.0\`，另有 `8.7.0` 历史 settings） |
| 进程树 | `douyin.exe` 主进程(PID 21872) + 7 个子进程 + `douyin_guard.exe`（守护）+ `douyin_tray.exe`（托盘，位于 `8.8.0\tray\`） |
| 版本签名 | ProductVersion 8.8.0.0，CompanyName **Beijing Microlive Vision Technology Co., Ltd.**（抖音直播伴侣主体） |
| 技术形态 | **Electron 应用**（`LICENSE.electron.txt`、`resources/app.asar` 15MB、chromium pak/icudtl）+ 原生推流栈（`ffmpeg.dll`、`SDL2.dll`、`PresentMon`（性能叠加）、`capture_service_client.dll`（系统采集）） |
| 附属组件 | `game_desktop_widget\douyin_game_widget.exe`（**互动玩法桌面挂件**，manifest 引 `@ies/game_ai_assist_sdk`）、`douyin_doctor.exe`（修复工具）、`elevation_service.exe` |

### 1.2 本地端口与接口（关键结论：无可旁听数据接口）

- **全部 `douyin.exe`/`douyin_guard.exe` 进程均未监听任何本地端口**（`netstat` + `Get-NetTCPConnection` 全量核对；全部连接均为对字节系 CDN/边缘节点的出站 HTTPS）。
- 唯一伴侣家族的监听：`douyin_tray.exe` → `127.0.0.1:8901`。实测：非 HTTP 服务（`GET /` 无 HTTP 响应），定位为**托盘单实例/通知 IPC**，与互动数据无关。
- `app.asar.unpacked/LANService.js` + `bonjour-service`/`multicast-dns`：**mDNS 局域网设备发现**（手机互联/无线摄像头类功能），不是数据 API。
- `8.8.0/data` 目录只有 `icudtl.dat`（无本地业务数据）；用户数据在 `%APPDATA%\douyin`（Electron userData）。

### 1.3 业务与数据通道形态

- asar 内代码与 `%APPDATA%\douyin` 证据显示：伴侣的**业务界面（含互动/数据面板）是远程加载的 H5 页面**，本地仅是壳（页面白名单出现 `www.douyin.com`、`live.douyin.com`、`sso.douyin.com`、`minigame.zijieapi.com` 等）。
- 域名证据（asar 内域名白名单/常量）：`imapi.douyin.com`（IM 接口）、**`frontier-pc.douyin.com`（字节 Frontier 长连接网关，PC 端消息推送通道）**、`ecom.douyin.com`、`www-hj.douyin.com`；Local Storage 中可见 `lf-webcast-gr-sourcecdn.bytegecko.com`（webcast 静态资源 CDN）。
- 伴侣日志（`parfait/alog`）为压缩遥测格式，无可提取的明文接口清单；`TTNetCache/netlog` 为空。
- **结论：主播侧互动数据经由"登录态 + 云端认证接口（imapi / frontier 长连接 / webcast 系）"下发到伴侣，本机没有任何明文本地接口可供第三方程序旁听。**

### 1.4 安全红线（本报告的硬约束）

以下做法**明确不采用、也不建议任何人采用**：
- 向 `douyin.exe` 注入 DLL / hook WebSocket / 内存读取——侵入式修改官方客户端，直接违反用户协议，**有封号风险**；
- 复用伴侣/主播登录态调用云端私有接口（imapi/frontier 私有协议）——等同于冒充官方客户端，风控可检测（客户端指纹/签名），同样有封号风险；
- 抓包解密伴侣 TLS——同上，且工程上等价于逆向私有协议，协议随版本变动，维护成本极高。

## 二、官方/生态路线（网络调研结论，2026-11-17）

### 2.1 抖音「直播小玩法」（唯一的官方点赞推送通道）——✅ 可行但门槛高

- **官方定位**：`developer.open-douyin.com/docs/resource/zh-CN/interaction/`（板块名"直播玩法"）。官方原话："直播小玩法由开发者自主开发，接入平台并开放给抖音主播挂载使用。"能力目录明确含**直播间点赞互动能力**、评论、礼物、粉丝团（幸运魔方等）。
- **事件类型**：官方 Unity SDK 消息枚举只有 `live_comment / live_gift / live_like`（+粉丝团）——**有点赞，无进场（member）事件**（来源：官方 SDK dump firevenus/LiveOpenSDK Types.cs）。
- **服务端推送协议**（第三方端到端实测，2026-02-13 验证通过，skyofzhang/DM_kpbl）：
  - `POST https://webcast.bytedance.com/api/live_data/task/start`（roomid+appid+msg_type，逐类型开启）→ 抖音服务器 **HTTP POST 推送到开发者公网 HTTPS 回调**（必须 HTTPS，Header `x-msg-type/x-roomid/x-signature`，MD5→Base64 签名）；
  - 点赞 payload：`msg_id, sec_openid, nickname, avatar_url, like_num, timestamp`，**`like_num` 是上游每 2 秒聚合的批量数**（非单次点击）；
  - 官方限制（引述）：QPS 默认 100、推送超时 2s（点赞）/3s（礼物）、连续 10 次失败熔断；另有**推送失败数据补偿查询接口**（task_fail_data_get，见 SKIT.FlurlHttpClient.ByteDance SDK Models/LiveData）——官方自己都承认推送可能丢、要做补偿；
  - 直播伴侣在此链路中的角色：开播时以 `game.exe -token=xxx` 拉起已上架的玩法客户端并传 token（webcastmate/info 换房间信息，token 30 分钟）。
- **接入门槛**：注册开发者+资质认证 → 创建小玩法 AppID → **玩法提案（飞书文档）评估过审 → 能力申请** → 开发（客户端需打包 exe）→ 提审上架。主体资质：2023 年口径"仅企业"；2025-11 教程口径"个人+软著可上架"（第三方转述，控制台内实际要求未核实）。审核周期官方未公布。
- **收益模式**：礼物流水分成（约 8%/单场，教程口径）。

### 2.2 抖音开放平台（DOP）直播 API ——❌ 不存在

- DOP OpenAPI 目录（2026-11-17 抓取）：个人资料/关系/内容/搜索/私信/数据开放/生活服务等——**无"直播"分类、无直播间互动/弹幕/点赞接口**；Webhooks 事件列表亦无任何直播间事件。抖店/百应只有事后经营数据接口。

### 2.3 直播伴侣官方扩展能力 ——⚠️ 无官方本地接口；社区有灰色方案

- 官网（streamingtool.douyin.com）无任何插件/SDK/回调文档；伴侣唯一官方扩展点就是 2.1 的小玩法挂载（伴侣"直播工具-游戏玩法"小扳手可填本地 exe 调试）。
- 社区逆向项目（公开、长期存在、**均未见封号案例报告，但也无官方授权**）：
  - **ape-byte/DouyinBarrageGrab**（1.7k★，v2.7.9 2025-04）：系统代理 MITM 解密 wss，可捕获 Chrome/抖音 PC 客户端/**直播伴侣**三源，v2.7.6+ 可 hook 伴侣进程；README 自带"仅供学习"声明；
  - wwengg/douyin（527★，2023 停更）：MITM 抓伴侣推流密钥+弹幕；
  - liupig/xiaokeai（439★，2026-11 活跃）：CDP 被动旁听 Chrome WS + 小玩法开放平台回调双通道（与本报告结论同构的混合路线）。
- **风险定性**：对伴侣 MITM/hook = 解密官方客户端 TLS/注入进程，直接踩《抖音用户服务协议》5.1（禁止自动化程序接入收集信息）；比观众端被动旁听风险面大一个量级，**不采用**。

### 2.4 主播后台对账 ——✅ 官方可导出指标级汇总

- 创作者中心/百应/罗盘：场次维度汇总指标（总点赞、互动率）可看/可导出；**无实时流、无逐条明细**；市面普遍用 RPA 采集罗盘指标这一事实反证官方无此类 API。适用定位：**事后对账**（校准本场总赞），不能做实时榜。

### 2.5 封号风险边界（条款与案例）

- 《抖音用户服务协议》（2026-02-20 生效版）明确禁止：2.4"爬虫"；**5.1"使用任何自动化程序、软件或类似工具接入抖音，收集或处理其中信息"**；5.3(4)"爬虫抓取"；处罚含"关闭账号、禁止重新注册"。
- **未检索到 2024-2026 年因"本机被动旁听直播间 wss 统计点赞"被处罚的公开案例**（DouyinLiveWebFetcher 2026-08 实测仍可用、DouyinBarrageGrab 长期公开），但条款层面任何抓取都在禁止之列——"社区无处罚报告"≠安全保证。
- 刑事风险参照：2022"爬虫第一案"（售卖抓取用户信息软件→侵犯公民个人信息罪）——红线在**售卖/收集他人个人信息**，本工具仅统计计数不存储敏感个人信息、不分发，但应继续保持单机自用。

## 三、主播侧路线对比表

| 路线 | 官方性 | 数据完整性预期 | 接入门槛 | 封号风险 | 适配本项目（本地单人工具） |
|---|---|---|---|---|---|
| ① 直播小玩法官方推送（live_like 等） | ✅ 官方 | 点赞=2s 聚合批量（openid/昵称/数量）；弹幕按条；**无进场事件**；有失败补偿接口 | 高：认证（个人需软著）+提案过审+公网 HTTPS 回调+上架 | 无（协议内） | **低-中**：需重构为"上架玩法"+维护公网回调；缺进场数据 |

## 四、对本项目的最终建议

1. **维持④为唯一实时数据源，叠加⑤做事后对账**：直播结束后在创作者中心/百应核对"本场总点赞"，与本工具 `LikeMessage.total` 口径对账（两者都是官方权威累计值，预期一致）；若发现偏差再排查。
2. **不触碰③**：伴侣 MITM/hook 虽然社区有现成项目（DouyinBarrageGrab），但解密官方客户端 TLS/注入进程是本项目"安全可靠、避免封号"约束下明确排除的动作。
3. **①是长期合规化路径**（如果未来产品化）：项目此前已放弃平台入驻路线；若重启，唯一官方形态是"上架直播小玩法"（点赞 2s 聚合推送+公网回调），需接受重构与审核成本，且进场数据缺口需用其他方式补。
4. **合规自护**（现状风险最小化）：保持单机自用、不商业化分发、不批量采集他人信息、不破解签名服务、控制连接数与频率（详见报告 B 的 4 连接上限）。
