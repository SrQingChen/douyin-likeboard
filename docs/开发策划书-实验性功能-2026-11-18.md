## 一、目标与选型

**目标**：把报告 B 4.2 节建议的完整率提升手段做成「设置页 → 实验性功能」折叠面板中的独立开关。全部功能**默认关闭**——不开启时系统行为与 v0.2.1 **逐字节一致**；开启后立即生效（热切换，不重启捕获）并伴随**独立日志**与**对照评分**（与未开启口径的多维度实时比对）。

### 选入的 4 个实验功能（全部来自报告 B 4.2「本机工程方案」）

| ID | 名称 | 报告出处 | 一句话 |
|---|---|---|---|
| EXP-1 | `totalAuthoritative` 权威总量口径 | B 4.2-1（"零风险，性价比最高"） | 房间级「本场点赞」显示改用 `total − 进房基线`（官方权威累计值，TikTok 官方生态同口径）；个人榜仍抽样 |
| EXP-2 | `fetchBackfill` 进房补帧 | B 4.2-2（"零额外请求"） | 被动旁听页面自发的 `/webcast/im/fetch`（`need_persist_msg_count=15`）响应，最近 15 条持久化消息按既有管线入账 |
| EXP-3 | `adaptiveTabs` 自适应并发 | B 4.2-3（"先灰度观察"） | 60s 窗口 coverage < 97% 持续 30s → 采集路数 +1（上限 4）；> 99.5% 持续 5min → 回落基线；运行时调路不重启 |
| EXP-4 | `dualBufferRoom` 双缓冲换房 | B 4.2-4 | 换房两阶段：首路先导航、`domcontentloaded` 后其余路再切；旧标签等待期保留旧房推送；标签在浏览器启动时预开（仅 flag 开启时） |

### 明确不做的

裸直连 WS / 主动 im/fetch 预取（B 4.2-5 排除）；伴侣 MITM/hook（A ③）；小玩法上架（A ① 长期路径）；后台对账（A ⑤ 人工操作）；按 total 差值放大个人计数（破坏公平）。

## 二、总体架构

### 2.1 配置（`server/src/config.ts`）

- `AppConfig` 新增 `experimental: { totalAuthoritative: boolean; fetchBackfill: boolean; adaptiveTabs: boolean; dualBufferRoom: boolean }`，默认全 false。
- **`loadConfig` 深合并**（核查修正：现状浅合并会让部分写入的 experimental 丢键）：`experimental: { ...DEFAULT_CONFIG.experimental, ...(raw.experimental ?? {}) }`，并对每个键强制 boolean 化。
- `patchConfig` 白名单新增 `experimental`：键级校验（仅 4 个已知键、值必须是 boolean），整体替换后落盘。

### 2.2 实验框架（新文件 `server/src/experiments.ts`）

```ts
export const EXP_KEYS = ['totalAuthoritative','fetchBackfill','adaptiveTabs','dualBufferRoom'] as const;
export type ExpKey = typeof EXP_KEYS[number];
export interface ExpDim { key: string; label: string; value: number; unit: string; hint?: string }
export interface ExpMetric {
  running: boolean; since: number;          // 开启时刻（关闭时 running=false 保留末次数据）
  dims: ExpDim[]; score: number;            // 各维归一化 0-100，总评=均值
  compare: Record<string, number|string>;   // 对照数值表：未开启口径 vs 开启口径
  lastEvents: string[];                     // 最近 ≤3 条事件摘要（节流更新）
}
```

- 独立日志 `data/experimental/<key>.log`：**懒创建**（首次写入才建目录）；append + ISO 时间戳 + JSON 行；超过 5MB 轮转为 `.old`（简单截断，复用 logrotate 思路）。同时以 `[实验:<名>]` 前缀走 `hub.log`（core.log + 控制台日志面板可见）。
- 开关切换 → `reset(key)` 重开计量（保留 lastEvents 清空）。

### 2.3 开关传递（热生效，不重启捕获）

- `capture-ctl.ts`：`captureEnv()` 注入 `EXP_FLAGS`（JSON 字符串）——保证捕获子进程重启后实验开关不丢。
- `agent.ts` / `agentCtl` 新增（默认关闭时**从不发送**）：
  - `{ t:'exp-flags', flags }` —— PATCH 保存后即时下发；**agent hello 后也重发一次**（核查修正：进程重启后同步状态）；
  - `{ t:'set-tabs', n }` —— EXP-3 运行时增/减标签；**agent hello 后重发当前 effectiveTabs**（浏览器 relaunch/进程重启不丢）。
- capture 侧 `expFlags` 初始读 `EXP_FLAGS` env，运行时收指令更新。

### 2.4 消息房间归属（核查新增，解决换房时序污染族）

- capture `likeBatch` 项新增可选字段 `r`（该消息来源页当时的 webRid）与 `bf`（backfill 标记 1）。**默认关闭（4 项全关）时不携带任何新字段，报文与现状逐字节一致。**
- core `agent.ts`/`engine`：收到带 `r` 的消息且 `r !== engine.agg.room.webRid` → 丢弃 + EXP-4/EXP-2 日志计数（跨房污染拦截）。`r` 缺失（= 全关态）→ 与现状一致直接入账。
- 何时携带 `r`：`expFlags.dualBufferRoom || expFlags.fetchBackfill` 任一开启时，capture 给所有 like 项打 `r`（每页在 `framereceived`/补帧解码时取该页 URL 的 webRid）。
- 补帧缓存：补帧消息在 capture 侧暂存，**直到该页所在新房间被 `roomMonitor` 确立并 `sendRoom(true)` 之后再随 200ms 批量发出**——保证 core 先切会话、补帧后入账，避免计入旧场或被 `!sessionId` 丢弃（核查 B-3/E-1 修正）。

### 2.5 UI

- `Settings.vue` 新增「🧪 实验性功能」折叠面板（默认收起）：每功能 = 开关 + 名称 + 说明 + 风险提示；下方实时评分卡（数据源 `roState.snap.exp`——App.vue 已建立全局 WS，Settings 引入 `shared/store.ts` 即可，无需新数据通路）。
- 快照只带标量 metrics + lastEvents 摘要（节流 5s 更新），**不广播轨迹/大数组**（OBS 浏览器源同享 /ws，控制体积）。
- `Dashboard.vue` **与 `Board.vue`**（核查修正：两处都消费 `sessionLikes`，必须同步）：仅当 `exp.flags.totalAuthoritative` 时「本场点赞」显示 `authoritativeLikes`（带"官方口径"小标），否则现状。

## 三、分功能详细设计

### EXP-1 totalAuthoritative（core + 前端）

**改动点**
- `aggregator.ts`：
  - `room` 新增 `baselineTotal: -1`（**字段初始化与 `resetSession()` 两处构造都要加**——核查 B-4）。
  - **baseline 锚定收敛为单点方法** `noteRoomTotal(v, source)`（核查 B-1 修正）：`roomTotal<0` 时锚定 `roomTotal=v; baselineTotal=v`；此后仅按既有单调/回退规则更新 `roomTotal`。`engine.onRoom`（DOM 首帧）与 `addLike`（首条 total）**都改走它**；`source` 记录来源（`'dom'|'ws'|'bf'`），**`bf` 来源不锚定**（补帧 total 是进房前历史值，锚了会把历史赞算进本场——核查 B-2/外部调研第 5 节修正）。
  - `authoritativeLikes()`: `roomTotal≥0 && baselineTotal≥0 ? max(0, roomTotal−baselineTotal) : −1`（−1=无效；负值回退 −1——核查 B-5 修正）。
  - **计数路径零改动**（纯观察字段）。
- `index.ts` 快照 `room.authoritativeLikes`（−1=无效，不照抄 roomTotal 的归零逻辑——核查 H 修正）。
- `Dashboard.vue` + `Board.vue` 按 flag 切换显示。

**评分维度（对照 = `sessionLikes` 未开启口径）**：①权威口径可用率（有效时长占比）②抽样偏差可见度（`sessionLikes/authoritativeLikes`，防除零）③增量一致性（60s Δcounted/Δauthoritative）。
对照数值表：sessionLikes vs authoritativeLikes + 差值 %。
**日志**：`baseline-anchored`（值/来源）、`fallback`、`summary`（5min）。

### EXP-2 fetchBackfill（capture + core）

**改动点**
- **新文件 `server/src/capture/backfill.ts`（纯函数，可 import 测试——核查 G 修正）**：
  ```ts
  export function decodeImFetchBody(body: Buffer): { method: string; payload: Buffer }[]
  ```
  **三形态解码**（外部调研核查修正）：①整体 magic `1f 8b` → `zlib.gunzipSync`；②首字节 `{` → JSON（`data.messages[].method` 明文、`payload` base64；base64 后如仍 `1f 8b` 再 gunzip——多余防御，无害保留）；③否则按 **protobuf LiveResponse** 解析（messagesList=f1，每条 method=f1 string、payload=f2 bytes，用现有 `pb.ts` 解析器）。空 body / 解析失败 → 返回 `[]` 并携带原因（调用方记日志）。**绝不抛错。**
- `capture/main.ts` `wirePage` response 分支：URL 匹配 `/webcast/im/fetch` 且 `expFlags.fetchBackfill` 时读 `res.body()`（整体 try/catch——async 回调 rejection 必须自捕获；**判空 Buffer**——CDP 静默空路径，核查 C/外部调研第 3 节修正）→ `decodeImFetchBody` → `handleMsg(method, payload, {bf:1, page})` → 补帧缓存（§2.4）。
- **补帧不进速率环**（核查 C 的 P1 修正——防假高能冲刺/速度虚高/峰值污染）：
  - `likeBatch` 项 `bf:1` → core `engine.addLike(..., src:'bf')` → `aggregator.addLike` 对 `src==='bf'`：**只累加计数**（roundLikes/sessionLikes/counted/users ring 无、`lastActiveSec` 更新），**跳过 secRing/minRing/rateRing**（速率/冲刺/限额推断不受历史消息影响），**不调用 noteRoomTotal**。
  - `agent.ts` 解析 `bf` 字段透传（核查 C 修正：现有解析只读 i/c/u/t）。
- capture 计数器（解码数/接受数/拒绝数/Σcount/人数）随批量上报 `{t:'exp-metrics', key:'fetchBackfill', ...}` → core `ExpTelemetry`。

**评分维度（对照 = 仅 WS 流）**：①回补贡献率（backfillLikes/counted）②防重安全（去重拒绝率——过高=全重叠，过低=可疑）③首数据时延（进房→首条入账，对照记录首条纯 WS 时延）。
**日志**：`fetch-decoded`（消息数/method 分布/接受/拒绝）、`fetch-decode-fail`（原因+长度+前 16B hex）、`first-data`、`summary`。

### EXP-3 adaptiveTabs（core 决策 + capture 执行）

**改动点**
- `capture/main.ts`：`TABS` → `let curTabs`（初始=env）；指令处理新增 `set-tabs`：`n>curTabs` 补 `newPage`+同址 goto；`n<curTabs` close 多余页（保 `roomPages[0]`）；回执 `{t:'tabs-ack', n}`。**指令串行化**（核查 D-4 修正）：`watchRoom`/`set-tabs`/`reloadRoom`/`relaunch` 共用一个 promise 队列，杜绝并发补页/导航/关页。边界：`ctx` 为 null 时只记账不执行；`n` 钳制 1..4；未进房只改数字。
- **决策器纯函数化**（核查 G/D-1/D-2 修正）——放 `experiments.ts`：
  ```ts
  export function decideTabs(s: {windowCoverage: number|null; ratePerMin: number; effective: number; baseline: number;
    belowSince: number|null; aboveSince: number|null; lastChangeAt: number; changes: number[]}, nowMs: number): {tab?: number; reason: string}
  ```
  - 输入 `windowCoverage` 为 **60s 窗口口径**（`Δcounted/Δtotal`，由 aggregator 新增 `totalRing`（每秒 totalDelta 增量 ring）配合现有 `rateRing` 计算）——**不是**全场累计 `coveragePct()`（累计口径早期 deficit 永久压低、只升不降——核查 D-1 修正）。
  - **"近期有数据"门**：60s 窗口 Δtotal > 50 才参与判定，否则挂起（安静房间 `totalDelta<=0 恒 100` 误判——核查 D-2 修正）。
  - 规则：`windowCoverage<0.97` 连续 30s（`ratePerMin>600` 时缩至 15s）→ +1 路（≤4）；`>0.995` 连续 5min 且 `effective>baseline` → −1 路；升降后 60s 冷却；**滑动 30min 窗口内变化 ≤8 次**（防振荡，替代"单场 6 次"——频繁换房不重得预算）。
  - baseline=用户 `captureTabs`，永不高于 4（报告 B：上限维持 4）。
- core 侧 `effectiveTabs` 状态：agent hello 重发（§2.3）；`tabs-ack` 确认后才更新核心态（未确认 60s 重发一次，上限 3 次）。

**评分维度（对照 = 基线路数 coverage）**：①完整度提升（升路前后 5min 窗口 coverage 均值差，pp）②响应速度（跌破→升路完成延迟）③稳定性（30min 变化次数，≥8 计 0）④资源代价（平均 effective/baseline）⑤**多路 msgId 重叠率**（外部调研补强：同 msgId 跨标签重复比例——直接检验"并集>单路"假设真伪；capture 侧 LRU(5000) 采样 msgId→首见标签，重复到达计数上报）。
**日志**：`decision`（窗口 coverage/rate/持续时长）、`set-tabs-sent`、`tabs-ack`、`overlap-sample`（5min）。

### EXP-4 dualBufferRoom（capture）

**改动点（`capture/main.ts`）**
- **预开标签仅在 `expFlags.dualBufferRoom` 时执行**（核查 A-1 修正）：`launchBrowser()` 后补齐 `curTabs` 个空白页；`about:blank` 对 2s 状态机无影响（roomMonitor 只看 `roomPages[0]`，看门狗只认在房 URL——已核查 E-2/E-3）。
- `gotoRoom` 两阶段（flag 开启）：阶段 A `roomPages[0]` await `domcontentloaded`；阶段 B 其余页 goto。flag 关闭：维持 `Promise.all` 并行（现状）。**打点区分 watch 换房与 relaunch 恢复**（relaunch 无旧房可保，只计 watch）。
- 跨房污染由 §2.4 `r` 归属拦截兜底（阶段 B 前旧页消息带旧房 `r`，core 已切新房 → 丢弃计数，不进榜单）。
- **顺手修复预存在缺陷**（核查 A-5）：`wirePage` 以 `WeakSet<Page>` 去重（现状 `ctx.on('page')` 自动 wire + `gotoRoom` 手动 wire 双注册，每帧解码两次靠 msgId 兜底）——此修复对默认关闭态是**纯性能修复**（去重后单次解码、likeBatch 单份，core 计数结果不变，replay/dom-check 回归把关）。

**评分维度**：①新房首数据延迟（watch→新房首条数据 ms）②切换平滑度（切换期间旧房保留帧数>0 的换房占比——注意这些帧会被 `r` 归属拦截不入账，仅计数作平滑度证据）③全程切换耗时（A→B 完成）。
**日志**：`room-switch-start`、`phase-a-done`、`phase-b-done`、`new-room-first-data`、`preopen-tabs`、`cross-room-dropped`（拦截数）。

## 四、「默认关闭 = 与现状完全一致」保证清单（验收逐项核对）

1. config 无 `experimental` 键 → 深合并默认全 false，其余键不受影响。
2. 快照仅新增 `exp` 字段与 `room.authoritativeLikes`（−1），前端旧组件不读取；`dom-check` 24 项原样通过。
3. `PATCH /api/config` 白名单扩键不影响既有校验；单独 PATCH experimental **不触发捕获重启**。
4. capture：`expFlags` 全 false → response 监听不读 body、`gotoRoom` 走并行分支、预开标签不执行、`r`/`bf` 字段不携带、`set-tabs`/`exp-flags` 从不收到；`TABS`→`curTabs` 仅变量形式。指令串行化与 wirePage WeakSet 去重为**行为等价的正确性/性能修复**（双注册本就靠 msgId 去重兜出相同计数）。
5. 决策器只在 flag true 时被调用；`ExpTelemetry` 未开启不写日志文件（懒创建）。
6. 计数/去重/结算/档案链路：无 `bf`/`r` 时与现状完全同路径。
7. 回归门槛：`replay-test` 24/24、`dedupe-test` 8/8、`starguard-test` 16/16、`typecheck`、`ui build`、`dom-check` 24/24 + 新增 `experimental-test.mjs` 全绿。

## 五、测试计划（`server/scripts/experimental-test.mjs`）

**可测性前提（核查 G）**：im/fetch 解码抽 `backfill.ts` 纯函数；决策器 `decideTabs(nowMs)` 纯函数；两阶段导航抽 `planGoto(flags, pages)` 纯状态机（输入 flags → 输出动作序列：`['parallel']` 或 `['serial-first', 'serial-rest']`）。

1. 默认关闭回归：Aggregator+Engine 喂流 → 计数/榜单/快照与现状逻辑一致。
2. EXP-1：total 序列（乱序/回退/断崖>5000/负差）→ baseline 单点锚定（dom 先到/ws 先到两序）、bf 不锚定、authoritative 计算/回退、维度值域。
3. EXP-2：三形态合成响应（gzip+JSON、protobuf、空/坏 body）→ 解码正确/防御不抛；补帧与 WS 重复 msgId → 去重；`bf` 消息不进 secRing/rateRing（速率断言）；agent `bf` 透传。
4. EXP-3：窗口 coverage 序列 → 升/降/冷却/限频/数据门/上限；`coveragePct` 累计口径不被使用（构造累计<97% 但窗口>99% 的反例断言不升路）。
5. EXP-4：`planGoto` flag on/off 输出；`r` 归属拦截（core 收到 r≠webRid 丢弃并计数）。
6. ExpTelemetry：日志文件懒创建/格式/轮转、reset、metrics 结构。
7. config：experimental 深合并（部分键缺失）、patchConfig 键校验/持久化往返（**测试用临时目录，不写真实 config.json**——核查 G 修正）。

## 七、风险与边界

| 风险 | 缓解 |
|---|---|
| im/fetch 实机形态不明 | 三形态解码 + 失败仅记日志；不影响 WS 主链路；实机验证 |
| 多标签并集收益无外部数据（外部调研证实空白） | EXP-3 重叠率指标直接检验；上限 ≤4；先实验后转正 |
| EXP-3 同 did 多连接风控未知 | 路数轨迹+重叠率+coverage 全记录；开关随时关闭回落 |
