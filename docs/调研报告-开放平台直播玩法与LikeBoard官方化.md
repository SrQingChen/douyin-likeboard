## 1. 直播玩法路线 · 最新规则要点

### 1.1 形态与准入

- 正确形态 = **直播小玩法 → 弹幕玩法**：独立玩法客户端（exe）挂载在主播「直播伴侣」中，画面进推流。互动插件（玩法面板/卡片）**暂停新准入**；互动小玩法（半屏）未明确开放新开发者。
- 准入流程：注册+资质认证 → 创建弹幕玩法（AppID）→ **提案评估**（飞书文档 + Demo 视频，约 2 个工作日；评审维度=玩法创新/优质美术/直播契合；拒绝同质化）→ 能力申请 → 开发 → 包体提审（约 4 个工作日）→ 灰度上线。
- 资质硬门槛 = **软著**（非游戏类、名称与玩法基本一致、主体与入驻主体一致；每个玩法仅 1 次改名机会；普通流程 30~60 个工作日 → **关键路径，应最先启动**）。商标非必需。直播玩法本身不需要版号/小游戏备案（不用游戏 IP 即可规避）。

### 1.2 直播间数据能力（LikeBoard 官方化的核心）

- 提案通过后申请「获取点赞互动数据」（必选能力）+「获取礼物互动数据」「直播间评论互动数据」等，后台申请自动开通。
- 数据到达方式：**任务启动接口**（点赞/评论/礼物需分别启动任务）→ 平台 **HTTP 回调**推送至开发者服务端（回调地址**仅支持配置 1 个**）。
- 推送完整性：**官方也不保证 100%**——推送失败需补偿，回查能力一般仅覆盖礼物（24h、约 10 万条、无 ACK）；点赞/评论推送失败无回查接口。⇒ 即便官方路线，排行榜也应做幂等与容缺设计（LikeBoard 已有 checkpoint/coverage 思想，直接平移）。
- 其他要点：观众标识为 `open_id`（应用内稳定）；主播自身消息被过滤；**履约 ACK 必须接入**（不接无法过审）；access_token 2h 刷新；测试需私密账号+调试成员（每玩法最多 3 个测试账号）。

### 1.3 成本与收益

- 抖音云可降本 10~30%、免域名备案，但自建服务器+备案也可行；小规模每月几百~几千元。
- **云启动（移动主播）为可选项**——LikeBoard 榜单玩法主要服务 PC 主播（直播伴侣挂 exe），可先不做云启动，大幅缩减开发量。
- 收益：礼物互动分成，开发者服务费默认 8%（可在 8%~23% 调整），平台代扣结算。
- 周期：提案 2 工作日 → 开发 → 包体 4 工作日；**不含开发**整体 2~4 周。软著未提前办会卡 1~2 个月。

## 3. 推荐路径（方案 C）· 行动清单

1. **【用户】登录开放平台控制台**：查「拆弹数字局」提案结果（已提交 >2 周，应有结论）——无论结果如何都验证了通道与反馈质量；若被拒，拒因对新提案是免费情报。
2. **【用户】立即提交软著**（材料已在 `提交材料\02_软著申请\`，30~60 工作日关键路径）。LikeBoard 新玩法与拆弹数字局**各登记一个软著**（同一主体可多件），LikeBoard 软著名建议「点赞排位直播互动软件 V1.0」（避免"游戏"字样，保留 1 次改名额度）。
3. **【用户/共同】创建第二个弹幕玩法**（如「点赞排位 LikeBoard」），提交提案：Demo 直接用 LikeBoard 透明窗口实录（现成）；提案文档可由本项目 docs + 数字炸弹提案模板快速组装。差异化卖点：点赞零门槛全员参与、成就徽章体系、纪录轮换框、限额封顶梗。
4. **【Agent】LikeBoard v0.2.0 官方化改造**（提案期间并行）：
   - `server` 新增 `official-source`：HTTP 回调端点 + 任务启动客户端 + 履约 ACK + 幂等（open_id 主键，与现有 secUid 主键抽象合并为 `uid` 字段）；
   - `desktop` 玩法客户端改造：接收直播伴侣启动参数（token）→ 转交服务端换房间信息 → 玩法云启动参数兼容（`-screen-fullscreen 1` 等，Phase 2 再做云启动）；
   - 数据源双模：`official`（回调推送）与 `passive`（旁听）可切换，聚合层零改动。
5. 能力开通后联调 → 包体提审 → 灰度。

## 4. 待确认清单（提案/能力开通后自答）

- `live_like` 推送的精确字段与频率上限（控制台《直播数据开放规则》可见）；
- 一个玩法包内能否同时运行"旁听链路"作为降级（合规边界——建议官方版内不保留旁听，规避审核风险）；
- 抖音云 vs 自建服务器的最终选择（回调地址备案要求）；
- 拆弹数字局提案反馈与 LikeBoard 提案是否互相影响（同主体多玩法为常规操作，理论无碍）。
