# 调研报告 — 参考项目「抖音红包」（E:\zcodeAI项目\抖音红包）

> 调研时间：2026-11-07，由只读调研子代理完成 + 主代理复核。
> 目的：确认其数据接口技术路线可否支撑「直播间点赞排行榜」项目。

## 结论：完全可支撑 ✅

参考项目已实测验证的被动旁听路线，其 proto 解码层（`dy-fudai/server/src/sense/proto.ts`）可零改动复用。

## 1. 三个子项目

| 目录 | 定位 |
|---|---|
| dy-sniffer/ | 嗅探原型：sniff1-6.mjs 采集器 + decode.py 离线解码器 + frames*.jsonl 原始帧存档 |
| dy-fudai/ | 第一代完整系统（Sense→Brain→Actor→Guard，Fastify+Vue3+SQLite） |
| dy-grab/ | 第二代精简重构（perceive→target→act，OCR 主导） |

## 2. 捕获方式

- **patchright**（Playwright 反检测分支）`launchPersistentContext(channel:'chrome', headless:false)` 驱动本机真实 Chrome；
- `page.on('websocket')` + `ws.on('framereceived')`（CDP 网络事件）直接读 WS 二进制帧，TLS 由浏览器自解，**无需 mitm/证书注入**；
- **headless 下抖音降级为 HTTP 轮询（/webcast/im/fetch/，实测 73 次/90s）无 WS 推送 → 必须有头**；
- 房间发现：live.douyin.com 首页抓 `<a href>` 提取 6-13 位短 ID（web_rid）；**长 room_id（19 位）导航会落回首页**；
- 登录态：一次性扫码存 Chrome profile 目录即可长期复用；**弹幕/点赞流匿名也能收**（frames*.jsonl 即匿名采集），福袋类数据才必须登录。

## 3. 协议（实测固化）

```
WS 二进制帧（明文 protobuf PushFrame）
 f1 seqId / f2 logId / f3 service=8888 / f4 method枚举 / f5 headers / f6 "pb" / f7 "msg"
 f8 payloadList(bytes, gzip 1f8b08 开头)
   → gunzip → Response{ f1: messages[] }
     → Message{ f1: method 明文("WebcastLikeMessage"…), f2: payload bytes }
服务端心跳帧为纯文本 "hi"（2 字节）。
```

- 无 .proto 文件，全项目"无 schema 裸解析"（varint + wire-type 遍历，~40 行）；
- 项目纯收帧：不 ack、不 framesent、不构造 WS URL/签名（页面内抖音自家 JS 负责握手）。

## 4. WebcastLikeMessage 字段树（2601 帧离线解码实证，955 条点赞消息）

```
f1 Common：f1 method名 / f2 msgId(int64) / f3 roomId / f8 展示模板 / f24 在线计数
f2 count      ★ 本条点赞数（连击≈10，实测范围 1–42）
f3 total      ★ 房间累计点赞总数（严格单调递增；frames6 整体 Σcount=5551 / Δtotal=6951，嗅探录制自身完整度 79.9%——局部相邻帧满足 Δtotal==count）
f5 User：
   f1 id      ✗ 隐私打码用户为 111111（实测 173/955 条，与打码昵称数完全相关），其余为真实 uid——不可作唯一键
   f3 nickName ★ 约 18% 打码（"好***"）；打码名可被多人共用（实测"用***"对应 2 个 secUid）
   f9 avatarThumb（f1 是**直接的 repeated string URL 列表**，非嵌套 Image.url_list；部分为 small_DefAvatar.png 占位）
   f73 secUid ★★ 每用户唯一且不变（100% 存在）→ 聚合主键
   f1028 idStr（打码用户 "111111"）
```

> ⚠️ **int64 陷阱（评审代理实测）**：参考项目 proto.ts 的 readVarint 用 JS 32 位位移，>32 位的 varint（msgId/uid 均超）会被折叠损坏。本项目须自带 BigInt varint 或原始字节键，不可照抄。
> 连续样本 (count=10,total+10) 证明 count 语义=真实点赞增量（连点器场景同样成立）。

辅助流：WebcastChatMessage（f3 弹幕文本）、WebcastMemberMessage（f2 User、f3 房间人数、f10 action=1 进场）——User 结构同上可复用。

## 5. 服务架构（可借鉴）

- Fastify 5 + @fastify/websocket + @fastify/static，127.0.0.1 单端口（REST /api/* + WS /ws + 静态 ui/dist）；
- UI：Vue 3.5 + Pinia + Vite 6 + TS；
- 启动：bat 重建干净 PATH → 后台起 server → 轮询就绪 → 开浏览器；UI 有优雅关闭链路；
- better-sqlite3 在 Node 24 prebuild 可用。

## 6. 风控经验（被动监听视角）

- 被动旁听（只收不发）风控暴露≈0，匿名即可跑；
- 硬风控信号只认三类：验证页跳转 / webcast 接口 403/429 / status_code 95152（误报教训：passport 心跳、安全 SDK CDN 都曾误判）；
- 浏览器崩溃自愈、风控期停机是既定策略；点赞**主动**行为另有 60% 概率/随机间隔等拟人规范（本项目不点赞，不适用）。
