# 开发交接 · 多功能点赞统计助手

> 本地旁听版的技术说明。项目定位：Windows 本地运行的抖音直播点赞统计与榜单叠加工具，不依赖平台开放接口。

## 1. 技术栈

- Node 22+ / TypeScript（tsx 直跑）
- Fastify 5 + @fastify/websocket + @fastify/static
- better-sqlite3（WAL）
- Vue 3.5 + Vite 6 + Tailwind CSS 4
- patchright + 有头 Chrome（被动接收直播间 WS 推送）
- Electron（透明/绿幕榜单窗口）

## 2. 目录与进程

```
capture 子进程（patchright 有头 Chrome）
  └─ 直播间 WS 帧 → WebcastLikeMessage/Chat/Member → 200ms 批量上报
core（127.0.0.1:17730）
  ├─ 聚合：本轮/本场点赞、60s 速度、峰值、封顶推断
  ├─ 结算：轮次、冠亚季军、纪录、徽章
  ├─ 持久化：SQLite WAL + 头像缓存
  └─ WS hub：1s 榜单快照 + 冲刺/评论/结算事件
展示层
  ├─ 控制台 /
  ├─ 榜单 /board
  └─ Electron / OBS 浏览器源
```

关键文件：

| 文件 | 作用 |
|---|---|
| `server/src/index.ts` | core 装配、1s 快照、捕获按需拉起 |
| `server/src/aggregator.ts` | 计数、去重、速度、surge、排名 |
| `server/src/engine.ts` | 轮次结算、纪录/徽章、冲刺状态 |
| `server/src/capture/main.ts` | Chrome 捕获、房间状态机、自愈 |
| `server/src/capture-ctl.ts` | 捕获子进程监护/重启限流 |
| `ui/src/board/*` | 榜单、领奖台、冲刺动效 |
| `ui/src/console/*` | 控制台、用户库、轮次、设置 |

## 4. 数据与兼容

- 数据库：`data/likes-stats.db`（首次启动自动从旧名 `likeboard.db` 迁移）。
- 登录态：`data/chrome-profile/`（捕获 Chrome 的持久化 profile；登录一次长期有效）。
- 配置：`data/config.json`；`autostartCapture` 只控制 core 启动时是否拉起捕获，不影响用户手动进房后恢复上次房间。
- 数据库/头像/配置均在本机，不上传云端。

## 5. 2026-11-11 修复记录

### 5.1 控制台操作 400

现象：立即结算、刷新页面、重启捕获、打开榜单窗口等无 body 的 POST 返回 400。

原因：前端 `api()` 对所有请求都加 `content-type: application/json`，Fastify 对空 JSON body 报 `FST_ERR_CTP_EMPTY_JSON_BODY`。

修复：`ui/src/console/api.ts` 只在有 body 时设置 JSON content-type。

### 5.2 捕获浏览器无限重启（“反复被踢出直播”）

现象：捕获窗口每隔 ~8 秒关闭重开，房间反复丢失，最后 `browser-relaunch-limit`。

根因有三层：

1. `ctx.on('close')` 不判断上下文引用：`relaunch()` 关闭旧上下文后，旧 close 事件又安排下一次 relaunch，形成自循环。
2. `watchRoom` 与启动流程可能同时 `launchBrowser()`，两个 launch 互相用 `killStaleChrome` 清理，导致刚启动的 Chrome 被另一个 launch 杀掉。
3. profile 被上一轮残留 Chrome 占用时首启失败，进一步触发重启。

修复：

- `ctx.on('close')` 比较 `ctx === myCtx`，旧上下文 close 不再触发重启。
- `ensureBrowser()` 单飞（同一时刻只允许一个 launch）。
- `relaunch()` 加 `relaunching` 守卫与单例定时器，先置空 `ctx` 再关闭旧上下文。
- `launchBrowser()` 前按 profile 精确清理残留 Chrome。
- `capture-ctl`/core 停止时不再误杀新实例。

### 5.3 手动进房不生效

现象：`autostartCapture=false` 时，输入房间号返回 queued，但捕获永远不进房。

原因：`/api/watch` 拉起捕获后依赖 hello 的 resume URL，而 resume 只在 `autostartCapture=true` 时返回。

修复：`getResumeUrl` 始终返回 `lastRoomUrl`；`onStartCapture` 改为 `ensureCapture()`（captureCtl 未创建时按需创建）。

### 5.4 安静房间一直显示“启动中”

修复：捕获检测到房间页面后立即上报 `watching`，不再等第一条点赞消息。

### 5.5 捕获日志不落盘

修复：`Hub.log()` 统一 `console.log`，capture 子进程日志也进入 `data/core.log`；便于排障。

### 5.6 新轮结算残留冲刺

修复：结算时清空 `engine.surge`；前端在轮次切换时也立即清除旧冲刺态。

### 5.7 星守护识别与宝石行

- **识别**：真实房间抓包确认，抖音 `User` 的粉丝团勋章结构 `f24 → f1(data) → f4(badge) → f1(icons map) → f2(Image) → f1(url_list)` 中，星守护会出现 `star_guard_advanced_badge_N_xmp.png`。`capture/main.ts` 的 `parseUser` 直接扫描 User 字节里的 `star_guard_` 标记（不依赖 proto 版本），随 profiles 上报 `sg`。
- **持久化**：`users.star_guard`（0/1，见即置 1）。
- **展示**：只对 **第 4 名及之后** 的榜单行生效；作者（`server/src/author.ts` 的 `AUTHOR_SEC_UIDS`）与星守护用宝石行，其余仍是原玻璃条。
- **作者 ID**：2026-11-11 实测同一账号（头像一致）在库里出现过两个 secUid，`AUTHOR_SEC_UIDS` 同时收录；以后若再变，把新 ID 追加到 `server/src/author.ts` 与 `ui/src/shared/format.ts` 两处。
- **彩虹名**：40px 周期 8 色重复渐变 + `saturate/brightness` + 暗色投影/描边；短昵称在宝石晶面上也能看清多色。
- **前三名**：领奖台（Podium）三座奖台也铺 `GemFacets` 水晶面——冠军金 / 亚军银 / 季军铜；若该位是作者/星守则改用其宝石色（作者=彩虹），作者昵称在领奖台同样彩色流动。
- **用户库**：`Users.vue` 用与 4+ 同款的横条列表；宝石色优先取手动色 → 当前榜单实时色 → 作者彩虹 → 星守按 secUid 稳定取色。
- **颜色**：`users.gem_color` 为 `null` 时，作者默认 `rainbow`，星守每场首次出现随机一色（`Aggregator.gemColors`，`resetSession` 清空）；手动设置后永久固定。`PATCH /api/user/:secUid/gem`，合法值 `null` / `rainbow` / `#RRGGBB`。
- **前端**：`ui/src/board/GemFacets.vue` 用 secUid 做种子画确定性晶面（不规则抖动网格 + 共享高度场：顶点高度含粗控制点起伏与局部扰动，Newell 法线算出每面 3D 朝向，亮度 = 法线·左上光源；约 1/3 格子合并成四边形；只画最受光边的两端渐隐倒角高光，背光边不描线；canvas 0.35px 轻模糊统一晶面），保留透明通道；静态色只绘制一次，作者 `rainbow` 用 canvas 按 ~30fps 重绘（16s 周期、左上→右下 0.30 对角滞后、完整 360° 闭环色相 + 正弦速度扰动，p=0/1 颜色与导数连续），CSS 只叠一层斜向镜面高光。

### 5.8 关闭系统

- `/api/shutdown` 先返回 `{ok:true}`（延迟 300ms 再执行），避免 `process.exit` 抢在响应之前导致前端无确认。
- `index.ts` 关闭顺序：结算 → `captureCtl.stop()`（进程树）→ 按 profile 清理残留 Chrome → 关闭项目 `desktop` 的 Electron 窗口 → 关 server。Electron 用 `CommandLine.Contains(desktopPath)` 匹配（注意这里不是正则，反斜杠不要二次转义）。
- 控制台收到响应后显示「系统已关闭」页，并说明捕获浏览器/榜单窗口已关闭。
- 关闭中快照定时器直接跳过，避免关闭 DB 后继续 `statsSummary()` 抛错。

### 5.9 身份主键修正（f46，重要）

- **f73 不是稳定 secUid**：实测同一 `User.f1` uid 在 42 秒内产生 158 个不同 f73，页面重载后全部变化；它是 1.0.3 格式的轮换令牌。此前用它做聚合主键，导致同一账号跨场/跨会话被拆成多个用户（作者 ID “变化”就是这个原因）。
- **f46 才是稳定 secUid**：1.0.0 格式 `MS4wLjABAAAA...`，账号级稳定。`messages.ts` 已改为 `secUid = f46 || f73`；打码用户（f46 缺失）只能退回轮换 f73，无法跨消息聚合（待后续决定是计数不入榜还是其他策略）。
- **所有用户**：`parseUser` 统一 `secUid = f46 || f73`；普通用户全部走 f46，只有打码用户（无 f46）退回轮换 f73。
- **作者稳定绑定**：2026-11-11 从真实 MemberMessage 抓到作者 `Sr_青尘` 的稳定 f46 = `MS4wLjABAAAAhs9HSVhGCISlyr4RzfOhVsF24VwtOg_SfIx3xGlFVm8`（数字 uid 97905874098）。`server/src/author.ts` 与 `ui/src/shared/format.ts` **只认这个 f46**，已删除 f73 列表和头像/昵称启发式；换头像、改名、换场都不影响。

### 5.10 启动首屏数据加速

- 进房后 ~4.7s 的 `WebcastRoomUserSeqMessage` 已带在线人数（f3；f9 为同值字符串兜底），`WebcastRoomStatsMessage` 的 f5 也可用；捕获层解析后立即 `sendRoom`，不再等 `MemberMessage`。
- 房间累计赞：进房后页面头部会显示「4001本场点赞」，`detectRoomStats()` 从 DOM 解析（支持「1.2万」），作为 `room.likeTotal` 首帧上报；核心只在 `roomTotal < 0` 时采用，后续以 `LikeMessage.total` 为准。
- 控制台/榜单改用 1s WS 快照（而不是 3s `/api/status`），未就绪显示 `—` 而非 0。
- 仍无法避免的是 Chrome 启动 + 页面加载本身（约 4~8s）；安静房间不再需要等第一条点赞/进场。

### 5.11 设置持久化 / 并发数 / 去重

- **持久化**：`patchConfig` 白名单落盘到 `data/config.json`；`loadConfig` 启动时合并默认值。危险区「清空全部数据」现在**保留 config.json**，不再把设置一起删掉。
- **窗口列表条数**：`boardCount`（默认 10，不含前三，范围 3~100）决定榜单窗口默认显示条数；快照每秒带 `boardCount`，Board 的 `maxRows` 用它，保存后 1 秒内热生效。chroma 窗口不再硬编码 `max=8`；不做紧凑压缩，窗口高度不足由采集端缩放/拉高。
- **并发数**：`captureTabs`（1~4，默认 2）进入设置页；`capture-ctl` 用它设置子进程 `CAPTURE_TABS`。保存时若捕获在跑，自动 stop→start 一次生效。
- **去重**：双标签实测同一 LikeMessage 的 `msgId` 完全一致（11/11 重叠，字段一致），`msgId` 作为主键正确；`seenMsg` 50k 容量（1000msg/s ≈ 50s），跨标签重复在毫秒级到达，足够。补了缺失/`"0"` msgId 的兜底键 `(secUid,total)`；`dedupe-test.mjs` 8/8。

## 6. 捕获参数

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `captureTabs`（设置页） | 2 | 并发标签数（1~4）；保存后捕获在跑会自动重启。旧的 `CAPTURE_TABS` 环境变量不再覆盖配置 |
| `CAPTURE_FORCE_CHANNEL` | 空 | `bundled` 强制用内置 Chromium（无系统 Chrome 时） |
| `CORE_WS_URL` | `ws://127.0.0.1:17730/agent` | core 接入地址 |
| `CHROME_PROFILE_DIR` | `data/chrome-profile` | 捕获登录态目录 |

捕获窗口必须保持打开；被误关会在 8 秒后自动重开。若抖音要求登录，请直接在捕获 Chrome 窗口登录（登录态只保存在本机 profile）。

## 7. OBS / 直播伴侣

- 首选：OBS 浏览器源 `http://127.0.0.1:17730/board?transparent=1`（真透明，推荐 560×960）。
- 窗口采集：实测 OBS「窗口采集」选「多功能点赞统计助手」可直接获得带 alpha 的画面（2026-11-11 实测）。
- 直播伴侣：高级功能「绿幕抠图」实际**消费窗口透明通道**（不是要求绿色背景）；常规透明窗口即可，相似度调到最低避免误伤正常区域。绿幕窗口仅作个别采集端不识别 alpha 的兜底；另一条路是 OBS 浏览器源 → OBS 虚拟摄像头 → 直播伴侣「摄像头」源。
- 绿幕兜底模式 CSS 已把 glass/宝石行/水晶台改为完全不透明，避免绿底透过卡片被抠掉（仅 `--chroma` 时生效，常规透明窗口不受影响）。
- 兜底：个别采集端版本列表不显示/丢 alpha 时，用控制台「OBS 兼容窗口（绿幕）」或 `打开榜单窗口-OBS兼容.bat`，采集端加 Chroma Key。
- 不要给真实 Electron 看板窗口注入 `WS_EX_LAYERED` 色键（实测渲染异常）。

## 8. Windows / 工程坑

- bat 必须 ASCII + CRLF；延时用 `ping -n`，不要用 `timeout`。
- 便携包 zip 用 PowerShell Compress-Archive（保留 UTF-8 文件名）。
- Electron 单实例锁只给榜单窗口；`--setup` / `--chroma` 跳过，否则先开榜单再启动会静默退出。
- 透明 Electron 窗口不要直接注入 `WS_EX_LAYERED` 色键：真实 Chromium 看板会出现色键不生效/渲染异常；需要独立原生 helper 才能做“隐形绿幕”。
- SQLite 使用 WAL；异常退出后重启会恢复未完成轮次并标记 interrupted，不补发奖项。
